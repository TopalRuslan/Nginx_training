# Task 2 — nginx перед приложением

Есть Todo-приложение из двух программ, каждая в своём контейнере:

| Контейнер | Что это | Порт в контейнере | Порт на хосте |
|---|---|---|---|
| `todo-web` | фронтенд на Node.js — отдаёт страницу, стили и JavaScript | `3000` | `3300` |
| `todo-api` | бекенд на Python — хранит задачи, отвечает на `/api/...` | `5000` | `5500` |
| `nginx-train` | nginx, который настраиваем | `80` | `8088` |

Контейнеры обращаются друг к другу по имени и порту в контейнере (`todo-web:3000`),
а браузер на хосте — по порту на хосте (`localhost:3300`).

Настроим nginx так, чтобы всё приложение открывалось по одному адресу
http://todo.localhost:8088, а nginx сам решал, кому передать запрос:

| Адрес | Куда передаёт nginx |
|---|---|
| `/api/...` | `todo-api:5000` |
| всё остальное (`/`, `/about`, `/style.css`…) | `todo-web:3000` |

## Стенд

```powershell
docker compose up -d --build --force-recreate
docker exec -it nginx-train bash
```

## Домен `todo.localhost`

Браузеры (Chrome, Edge, Firefox) любое имя вида `что-угодно.localhost` отправляют на ваш
компьютер — `127.0.0.1`. Поэтому для локальной проверки подойдёт домен `todo.localhost`,
ничего дополнительно настраивать не нужно.

Nginx смотрит, какой домен набран в адресной строке, и выбирает сайт с таким `server_name`.
Если подходящего нет — отвечает сайт по умолчанию (`default`, «Welcome to nginx!»).

## Задание

1. Открой приложения напрямую, без nginx:
   - http://localhost:5500/api/todos — бекенд отвечает JSON со списком из двух задач по умолчанию;
   - http://localhost:3300 — фронтенд открывается, но пишет, что API не отвечает, а на схеме
     вверху горит только `todo-web`. Фронтенд сам не умеет ходить в бекенд — это и будет делать nginx.

2. Создай конфиг `/etc/nginx/conf.d/todo.conf`.

   Nginx сам читает все файлы `*.conf` из папки `conf.d` — это прописано в `nginx.conf`
   строкой `include /etc/nginx/conf.d/*.conf;`. Поэтому достаточно положить туда файл,
   больше ничего делать не нужно. Имя обязательно должно заканчиваться на `.conf`.
   `default` не трогай — он нужен, чтобы увидеть разницу между доменами.

   ```nginx
   server {
       listen 80;
       server_name todo.localhost;

       location / {
           proxy_pass http://todo-web:3000;
       }

       location /api/ {
           proxy_pass http://todo-api:5000;
       }
   }
   ```

   | Строка | Что делает |
   |---|---|
   | `server { }` | Один сайт и все его настройки |
   | `listen 80` | Порт, на котором сайт принимает запросы |
   | `server_name todo.localhost` | Домен сайта: запросы на `todo.localhost` попадут сюда |
   | `location / { }` | Правила для всех адресов, кроме тех, что описаны отдельно |
   | `location /api/ { }` | Правила для адресов, которые начинаются с `/api/` |
   | `proxy_pass http://todo-web:3000` | Переслать запрос приложению и вернуть его ответ. `todo-web` — имя контейнера |

   Nginx выбирает самый длинный подходящий `location`: `/api/todos` подходит под оба,
   но `/api/` длиннее, поэтому запрос уйдёт в бекенд.

3. Проверь конфиг и примени:

   ```bash
   nginx -t && systemctl reload nginx
   ```

4. Проверь в браузере:
   - http://todo.localhost:8088 — на схеме горят все узлы. Добавь пару задач, отметь одну
     выполненной, открой «Как это работает» и обнови страницу.
   - http://localhost:8088 — «Welcome to nginx!»: домен другой, поэтому ответил `default`.

## Дополнительно: где могут лежать приложение и конфиг

Это две разные вещи.

**Приложение — где угодно.** Nginx не важно, где лежат файлы приложения, — в конфиге
ты сам указываешь, куда смотреть:

- статические файлы из любой папки:

  ```nginx
  root /home/user/projects/my-site;
  ```

- приложение, которое запущено отдельно, — по адресу и порту:

  ```nginx
  proxy_pass http://127.0.0.1:3000;
  ```

В этом задании фронтенд и бекенд вообще лежат в других контейнерах — nginx просто
пересылает им запросы.

**Конфиг — там, откуда nginx его читает.** При старте nginx читает один файл —
`/etc/nginx/nginx.conf`. Остальные конфиги он видит, только если они подключены через
`include`. В Ubuntu по умолчанию подключены две папки:

```nginx
include /etc/nginx/conf.d/*.conf;
include /etc/nginx/sites-enabled/*;
```

Поэтому проще всего класть конфиг туда. Но если хочется держать конфиг рядом
с приложением, например в `/opt/myapp/nginx.conf`, есть два способа:

- добавить свой `include` в `nginx.conf` внутри блока `http { }`:

  ```nginx
  include /opt/myapp/nginx.conf;
  ```

- сделать ярлык из папки, которую nginx уже читает, на файл в папке приложения:

  ```bash
  ln -s /opt/myapp/nginx.conf /etc/nginx/conf.d/myapp.conf
  ```

В обоих случаях файл физически лежит в папке приложения, а nginx его находит.
